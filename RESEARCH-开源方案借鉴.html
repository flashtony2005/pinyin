面向当前 Rust + Native Shell 的「拼音拼读」App：调研同类开源项目的功能与 UI 做法，判断哪些能借鉴到本项目，并给出按优先级排序的落地清单。

调研范围：GitHub 拼音学习类项目 对照基准：pinyin-pal v0.1.0 结论：代码无需重写，缺的是「教学信息层」与「练习闭环」

2本项目现状：我们强在哪、缺在哪

先看清家底，避免盲目照搬。真的去抄界面，反而可能丢掉我们已有的优势。

已经领先的点（别丢）

  • 全离线真人发音：1069 个百度真人分声调 mp3 + 40 个 TTS 兜底，压缩后仅 4.2 MB。多数同类用系统 TTS 或依赖联网 Gemini Key。
  • 一屏铺满、无滚动：声母/韵母分行等分高度，移动端体验干净，很多 Web 项目在手机上还要滚动。
  • 组合合法性过滤：按 343 音节矩阵置灰非法组合（b+ong），教学准确。
  • J/Q/X/Y + ü 书写规则：spell() 已正确处理 ju/que/xun 等，逻辑到位。
  • 真跨端：一套 Rust 出 Android/Web/桌面，Android 已真机验证。

真正的缺口

  • 只有拼音、没有意义：拼出 ba 只显示「ba」，没有例字「八」、例词——孩子不知道这个音对应什么。
  • 缺教学提示：ü 为什么写成 u、声调该标在哪个字母上，代码里有逻辑但用户看不到解释。
  • 没有记忆锚点：无顺口溜、无字形助记，b/d/p/q 这类易混字母缺辅助。
  • 没有整体认读类别：16 个整体认读音节散在音节表里，没有作为独立概念呈现。
  • 只有「学」没有「练」：无听音辨字、无小测，缺少闭环与成就感。
  • 不支持三拼：jia/gua 等三拼音节当前 compose 直接判为 Invalid。
关键发现：我们项目最大的短板不是 UI，而是「拼出来之后没有信息量」。而且补这个短板的数据已经躺在仓库里——tools/speak_map.json 里有 366 个音节的例字（ba→芭、ma→妈、zhong→中、yi→一），当初是为 TTS 兜底生成的，现在可以直接复用到界面上。这是投入产出比最高的一步。

3分层借鉴建议

按「改动成本 × 教学收益」分三档。建议按顺序推进，每档做完在真机上验证再进入下一档。

P0 · 立刻做

数据现成 / 改动极小 / 收益最直接
  • 拼读结果显示例字复用 speak_map.json；注意它是「第一声同音字」，展示时可与当前声调解耦或标注「例字」
  • ü 拼写规则提示当选中 j/q/x/y + ü 时，结果卡补一行「ü 遇到 j q x y 写作 u」
  • 标调规则说明「有 a 找 a，没 a 找 o e，i u 并列标在后」——chen2qu 的做法，一段文案即可
  • 顺口溜助记声母/韵母卡片点开后显示一句口诀，可先做 23 个声母

P1 · 值得做

中等改动 / 补上「练」的闭环
  • 听音辨字小游戏播放发音，从 4 张例字卡里选正确的——candy / plain-pinyin 的核心玩法
  • 整体认读独立类别把 16 个 zhi/chi/shi/yi/wu… 单列成一个可点读的分区
  • 声调手势图用 ↗ ↘ 之类手势替代/补充抽象调号，更贴合低龄儿童——Pinyin-LeLe 做法
  • 三拼支持jia/gua 等，需扩展 compose 逻辑与音频映射，工作量较大

P2 · 慎做

风格冲突 / 工作量大 / 与定位不符
  • 整体换成马卡龙糖果风当前紫色极简风已成形，用户已反复打磨；大改风格风险高
  • 果冻按钮 / 全屏彩带动效nsh anim 成本较高，可作为答对反馈的小范围点缀
  • 整张拼音表 + 行列高亮与「一屏铺满拼读」主交互不同，可能做成第三个页签而非替换
  • 艾宾浩斯复习 / 错题本 / 成就需要本地持久化，属于「学习系统」范畴，超出轻量工具定位
  • AI 助记插画 / AI 老师需联网 + API Key，与本项目「完全离线」的核心优势冲突

为什么不直接照搬某个项目：它们几乎都是 Web 技术栈（React/Tailwind），代码无法直接用于 Rust + nsh。真正可迁移的是教学设计（例字、口诀、手势、听音辨字玩法）和数据结构（如 zxq432/py 的声调映射表）。本项目在发音质量和离线能力上已经领先，借鉴应聚焦「补齐信息量与练习闭环」，而非推倒重做 UI。

5结论

有值得借鉴的，而且不需要改架构。最高优先级是把现成的 366 个例字显示到拼读结果上——这一步改动不到 20 行，却让 App 从「只会读音」变成「能教会孩子这个音是什么字」。其次是补上 ü 与标调规则的文字提示、顺口溜助记。这四个 P0 项做完，教学完整度就能追上甚至超过多数同类开源项目。

中期可以做「听音辨字」小游戏和整体认读分区，把「学」补成「学+练」。糖果风换肤、AI 插画、错题本这类不建议做——前者与已打磨的 UI 冲突，后者与「完全离线」定位冲突。若后续要支持三拼或整张拼音表，可作为新的页签扩展，不影响现有主交互。
